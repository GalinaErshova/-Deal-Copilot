## Замечания

Порядок — от важного к мелкому. «Где» — файл и строка в commit `a7cf258`.

### 1. Нет учётных записей и прав — высокая важность

Где: `backend/app/main.py`, все маршруты, кроме `/api/admin/*`.

Любой, кто открыл сайт, может удалить сделку вместе с файлами (`DELETE /api/deals/{id}`),
изменить прайс-лист и формулы расчёта. Инструкция по развёртыванию это признаёт.

На сервере закрыто паролем на прокси (nginx, Basic Auth). Для рабочей эксплуатации нужны
вход пользователей и хотя бы разделение «менеджер» / «администратор прайса и формул».

### 2. `OLLAMA_MODELS` совпадает с переменной Ollama — высокая важность

Где: `backend/app/config.py:22`, `backend/.env.example`, `docs/deployment-nordik-mini-pc.md`.

Ollama хранит в `OLLAMA_MODELS` путь к каталогу моделей. На mini-PC эта переменная задана
(`C:\Users\Galina\.ollama\models`), и API падает при запуске: путь читается как имя модели,
а проверка требует `OLLAMA_BASE_URL`. Так упали все тесты при первом запуске. Инструкция
предлагает запускать API именно на mini-PC, то есть там, где переменная уже есть.

Исправление: переименовать настройку, например в `DEAL_COPILOT_OLLAMA_MODELS`, или задать
приложению общий префикс переменных через `env_prefix`.

### 3. Ответ модели сохраняется без проверки значения — высокая важность

Где: `backend/app/main.py:539–552`, `backend/app/schemas.py:7–16`.

При приёмке `qwen2.5:7b` вернула площадь как `log(1200)` и срок как `log(12)`. Значения
записались в карточку требований как есть. Расчёт потом отвечает «Подтверждённая площадь
указана некорректно», и пользователь не понимает, откуда ошибка.

Исправление: для числовых ключей (`area_m2`, `contract_months` и другие) приводить значение
к числу при сохранении, а нечисловое помечать статусом «требует проверки» и показывать
исходную цитату.

### 4. Ollama вызывается без размера контекста — средняя важность

Где: `backend/app/model_gateway.py:55–75`.

Фрагмент документа — до 12 000 символов, к нему добавляются системная инструкция и JSON-схема.
Это больше контекста Ollama по умолчанию (2–4 тыс. токенов в зависимости от версии). Ollama
молча отрезает начало запроса, и модель может не увидеть инструкцию.

Исправление: передавать `options.num_ctx` из настроек, например `OLLAMA_NUM_CTX=16384`,
и согласовать его с `LLM_INPUT_CHUNK_CHARS`.

### 5. Длинная обработка в одном HTTP-запросе — средняя важность

Где: `backend/app/main.py:468–559`.

Документ режется на фрагменты, каждый идёт в модель последовательно, с ожиданием до
`OLLAMA_TIMEOUT_SECONDS` на фрагмент. Крошечный документ на `qwen2.5:7b` обрабатывался 50 секунд.
Инструкция ставит прокси таймаут 180 секунд: на большом ТЗ браузер получит 504, а обработка
продолжится на сервере. Пользователь нажмёт ещё раз и запустит второй прогон.

На сервере таймаут прокси поднят до 900 секунд. Исправление в коде: фоновая задача
и опрос статуса прогона из интерфейса, запрет второго запуска, пока идёт первый.

### 6. Удалённая из списка модель роняет весь интерфейс — средняя важность

Где: `backend/app/model_gateway.py:110–117`, `backend/app/main.py:319–362`.

Если активный профиль убрали из списка моделей, `active_profile` бросает `ValueError`.
`/api/health` и `/api/settings` отвечают 500, интерфейс не загружается. Инструкция
предупреждает об этом, но защита должна быть в коде.

Исправление: в этих двух маршрутах возвращать понятное состояние «модель не настроена»,
а ошибку оставлять только для запуска обработки.

### 7. Повторная обработка стирает подтверждения пользователя — средняя важность

Где: `backend/app/main.py:533`.

`/process` удаляет все поля сделки, включая подтверждённые и введённые вручную, например
площадь. Предупреждения нет.

Исправление: сохранять подтверждённые поля или явно спрашивать в интерфейсе перед повторной
обработкой.

### 8. Ollama на mini-PC открыта всей локальной сети — средняя важность

Где: настройка mini-PC, не код.

Ollama слушает все адреса (`OLLAMA_HOST=0.0.0.0:11434`), правило брандмауэра
«Ollama WSL 11434» разрешает вход с любого адреса. Модели доступны любому устройству
в домашней сети и в обоих туннелях.

Рекомендация: в этом правиле ограничить удалённый адрес значением `10.66.66.16` (NORDIK)
и при необходимости `127.0.0.1`. Правило безопасности меняет владелец машины.

### 9. Изменение поля без проверки входа — низкая важность

Где: `backend/app/main.py:739–747`.

`PATCH /api/fields/{id}` принимает произвольный словарь. Без ключа `confirmed` поле считается
подтверждённым: любое изменение значения сразу подтверждает его.

Исправление: схема Pydantic для тела запроса и подтверждение только явным `confirmed: true`.

### 10. Тесты зависят от машины — низкая важность

Где: `backend/tests/test_api.py`, `backend/tests/test_api_flow.py`, `backend/app/db.py`.

Тесты API пишут в рабочую базу `backend/data/deal_copilot.db` и читают переменные окружения
машины, поэтому на mini-PC они падают (см. замечание 2).

Исправление: общий `conftest.py` с временной базой и очисткой переменных Ollama.

### 11. Мелкие недочёты

- `GET /api/deals` подгружает документы каждой сделки отдельным запросом — `main.py:370–383`.
- Отпечаток расчёта читает полный текст всех документов при каждом `GET /calculations` —
  `main.py:116–150`. На больших ТЗ это заметно замедлит вкладку «Экономика».
- Загрузка пишет файлы до записи в базу; при сбое посередине остаются файлы без сделки —
  `main.py:456–463`.
- В расчёте по строкам тариф, введённый вручную для строки из документа, игнорируется, если
  строка сопоставлена с прайсом, — `main.py:933–937`. Уточнить, задумано ли так.
- Боковая панель подписывает любую рабочую модель как «MiMo · API», в том числе Ollama, —
  `frontend/app/page.tsx`, подвал боковой панели.
- Ветка `codex/deal-history` шла без PR и без проверки CI. Лучше оформлять каждую ветку
  через PR.

## Расхождение с инструкцией по развёртыванию

Инструкция ставит API и SQLite на mini-PC, а сайт — на NORDIK. По заданию база на NORDIK,
модели на mini-PC, сайт на gala-msk. Поэтому API работает рядом с базой на NORDIK и ходит
в Ollama на mini-PC по туннелю. Фактическая схема — в `docs/deployment-state.md`.
